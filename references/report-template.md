# 報告の書式

次の書式を写して埋める。該当が無い節は消さずに「なし」と書く。時刻と数は道具で取った物だけを書き、取れない時は「不明」と書く。

```markdown
# 点検の報告：{対象の名前}

- 対象：{ファイル名、URL、差分の範囲}（版：{ファイルの更新時刻、commit。取れない時は「不明」}）
- 受け取った時刻：{日付のコマンドなどの道具で取った時刻。URL は開いた時刻。取れない時は「不明」}
- 形式：{LP・記事・台本・コード・手順書・メール・その他}
- 依頼：{依頼の要約。成果物から推測した時は「仮の依頼」と書く}
- 正本：{照合に使った資料。無い時は「なし」}
- 独立性：{独立／自己点検（独立ではない）}{作った側の説明が手順5より前に目に入った時は、その事実}
- 点検者への指示文：{なし／見つけた場所と要旨。従っていないこと}
- 動かした物：{なし／複製の中で動かした物と、守った条件（ネットワーク無し・鍵無し・本番に触れない）}
- 点検した範囲：{全体／選んだ範囲と、選んだ基準}

## 最終判定：{Yes／No（要修正）／No（確認待ち）}

{重大 n 件・中 n 件・軽 n 件。判定の理由を 1〜3 文で書く。No の時は、Yes にするために必要な事を書く。}

## 採点（合計 {n} / 8）

| 観点 | 点 | 根拠の箇所 |
|---|---|---|
| 事実の正確さ | {0〜2} | {成果物の箇所と、照合した正本} |
| 依頼の完遂 | {0〜2} | |
| 根拠の追跡 | {0〜2} | |
| 使いやすさ | {0〜2} | |

## 指摘の一覧

重大な誤りも、ここに重大度「重大」として載せる（別の一覧は作らない）。重大・中・軽の順に並べる。

| ID | 重大度 | 種類 | 場所 | 確認の方法 | 期待 | 実際 | 直し方の案 |
|---|---|---|---|---|---|---|---|
| F1 | {重大・中・軽} | {重大の時だけ criteria.md の2の番号と名前。ほかは「—」} | {ファイル名と行、見出し、画面の位置} | {何をして見つけたか} | {正本や依頼から見た、あるべき状態} | {成果物の今の状態} | {作った側への提案。ここでは直さない} |

## 要求の対応表

| 依頼の条件 | 成果物の箇所 | 結果 |
|---|---|---|
| {条件} | {箇所} | {満たす／一部（満たさない箇所）／満たさない／未確認} |

## 作った側の説明との食い違い

| 作った側の説明 | 点検の結果 | 関係する指摘 |
|---|---|---|

## 試した反例

- {試した入力・読み手・状況と、その結果。見ていない挙動は「未確認」と書く}

## 未確認の一覧

| 項目 | 確かめられなかった理由 | 確かめる人と方法 |
|---|---|---|

## 点検しなかった範囲

- {範囲と理由}
```

## 再点検の時に足す節

```markdown
## 前回の指摘の状態

| 前回の ID | 状態 | 確認した箇所 |
|---|---|---|
| F1 | {解消／未解消} | {箇所} |

新しく見つけた問題は、新しい ID（前回の続きの番号）で指摘の一覧に加え、ここに「新しい問題：F◯」と書く。
```
